# 계획·점검 문서 보관 규칙

이 폴더는 계획서와 점검표를 **날짜별로 쌓아 두는 곳**입니다. git 이력이 곧 변경 이력이므로 덮어써도 이전 버전은 남지만, 가능하면 새 날짜 파일로 추가합니다.

## 규칙
1. 계획서·점검표는 대화창이나 프로젝트 문서에만 두지 않고 이 폴더에도 커밋한다.
2. 항목은 번호만 쓰지 않는다. **번호 + 내용 + 근거 + 완료 기준**을 같이 적는다.
3. 가능하면 완료 기준을 자동 점검(테스트·DB 점검 규칙)과 연결하고 그 파일명을 적는다.
4. 번호 체계를 바꿀 때는 옛 번호와 새 번호의 대응표를 남긴다.

## 파일
- `2026-10-14_plan_v5.md` — 확정 계획 v5 원본(10-14 18:30 저장본). G7·G13 등 코드의 뜻이 여기 있음.
- `2026-10-25_G-items-lost.md` — G 항목 분실 기록과 대체 점검 방침.
