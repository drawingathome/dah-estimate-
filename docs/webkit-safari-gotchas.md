# 크롬(제 테스트환경) vs 사파리(선혜님 실기기) 렌더링 차이 체크리스트

> 제 테스트 도구(Puppeteer)는 크롬 엔진만 돌아가요. 사파리(WebKit)는 다운로드가
> 네트워크 정책으로 막혀있어서 직접 못 씁니다. 그래서 "제가 확인했다"고 해도
> 실기기와 다를 수 있어요. 아래는 오늘 실제로 겪은 차이점들 — 새 CSS 작성/수정 시
> 이 목록을 먼저 훑어볼 것.

## 확인된 실제 차이
1. **box-sizing 기본값 관련 폭 계산** — border-box 리셋 없이 패딩 있는 요소는
   실기기에서 지정폭보다 넓게 나올 수 있음 (2026-08-08 발견)
2. **flex/grid 자식의 min-width 기본값(auto)** — 텍스트가 길면 부모 폭을 넘어서도
   안 줄어드는 문제가 사파리에서 더 두드러짐. flex 자식엔 항상 `min-width:0` 명시
3. **date input의 ::placeholder 미적용** — `<input type="date">` 빈 상태 텍스트는
   placeholder 색이 아니라 기본 color를 씀 (2026-08-08 발견)

## 새 CSS 작성 시 항상 지킬 것
- flex/grid 자식에 텍스트가 들어가면 `min-width: 0` 명시
- 패딩/보더 있는 요소는 `box-sizing: border-box` (전역 리셋 있으니 이제 자동 적용됨)
- 폭 확정이 중요한 요소는 `max-width: 100%` 같이 걸어서 이중 안전장치

## 배포 후 확인 프로세스 (중요도 순)
1. 레이아웃 관련 수정은 **"확인했어요" 대신 "이렇게 될 것 같은데 확인 부탁드려요"** 로 표현
2. 선혜님이 실기기에서 확인해주시기 전까지 그 이슈는 "미해결"로 간주
3. 같은 증상이 재발하면, 이전 수정이 잘못됐다고 가정하지 말고 **"다른 원인이 하나 더 있었다"**는 가능성부터 확인 (오늘 실제로 그랬음: min-width 수정 → overflow-x:hidden → box-sizing, 총 3단계)
